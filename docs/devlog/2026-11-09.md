## 記得

- **Docker 還沒驗證過**：這台機器沒有 Docker。`pnpm deploy --prod` 這一步在本機模擬過可以跑，但 `docker compose up` 要在有 Docker 的環境確認
- 這台機器的 pnpm 是用 `npm install -g pnpm@9` 裝的
- Windows 上 `pnpm deploy` 不能部署到不同磁碟機（C: 到 D:），是 pnpm 的 bug
- **本機開伺服器來看**（沒有 Docker 的做法）：
  1. `pnpm --filter @mcp-gateway/server dev:db`：用 embedded-postgres 開一個本機 PostgreSQL，port `54329`，資料存在 `packages/server/.pg-dev/`
  2. 另一個終端機設好環境變數（`DATABASE_URL=postgres://gateway:gateway@127.0.0.1:54329/gateway`，其他照 `.env.example`；這一版 Entra 填假的 GUID 就可以），再跑 `pnpm dev`
  3. 打開 http://localhost:3000/
- **Windows 上關不乾淨**：直接 kill 背景程式時，postgres 的子程式（`--forkchild` 的 io_worker）會變成孤兒，繼續佔住 port。`pg_ctl stop` 也會等不到。要關的話在 `dev:db` 的終端機按 Ctrl+C；真的卡住就砍掉路徑在 `D:\mcp-gateway
ode_modules\` 底下的 `postgres.exe`

# #3 Sign in with Entra; Platform Admin via app role（2026-11-09 晚上）

## 完成了什麼

- **Identity**（`src/identity/identity.ts`）：OIDC authorization code + PKCE，打的是設定的那個 tenant 的端點。`beginSignIn(redirectUri)` / `completeSignIn(state, code)`，redirect URI 是參數，#14 的 OAuth 授權流程可以直接重用
  - 驗 ID token：簽章（JWKS）、`aud`、時間（用注入的時鐘，容許 5 分鐘誤差）、`tid`、`iss`、`nonce`
  - `tid` 不對 → `other_tenant`；其他問題一律 `failed`，細節只寫在 server log
  - app role 的值是 `PlatformAdmin`（常數 `PLATFORM_ADMIN_APP_ROLE`）
- **資料表**（第一個 migration `0000_users_and_web_sessions`）：`users`（以 `entra_object_id` 為唯一鍵）、`sign_in_requests`（10 分鐘過期，用 `DELETE … RETURNING` 確保只能完成一次）、`web_sessions`（只存 token 的 SHA-256）
- **Session**：存在 PostgreSQL（多 instance 可共用，配合 #18），cookie `mcpgw_session`，HttpOnly、SameSite=Lax、`PUBLIC_BASE_URL` 是 https 時加 Secure，**12 小時**後失效
- **登入 CSRF 防護**：開始登入時設 `mcpgw_sign_in` cookie（內容是 state），callback 時必須相符
- 路由：`GET /auth/sign-in`、`GET /auth/callback`、`POST /auth/sign-out`（204）、`GET /api/me`。`/api/*` 全部要 session，沒有就 401 `{error:"unauthenticated"}`；不存在的 `/api/*` 回 JSON 404
- 登入失敗導回 `/?sign_in_error=other_tenant|failed`，Web UI 顯示訊息後把參數清掉
- Web UI：登入連結、登入者名稱與 email、Platform Admin 標記、登出、「還不屬於任何 Workspace」提示
- 測試：`test/support/fake-entra.ts`（假的 Entra OIDC provider，用 `fake_person` 參數指定誰登入）、harness 加了 `Browser`（cookie jar、不自動跟 redirect）、`gateway.signedIn(person)`。新增 17 個測試，共 42 個
- README 加了 Entra app registration 需要的設定（redirect URI、app role、client secret）

# #4 Workspaces and membership（2026-11-09 晚上）

分支 `4-workspaces-membership`，疊在 `3-entra-sign-in`（PR #22）上。

## 完成了什麼

- **加入還沒登入過的人**：用 email（UPN）或 Entra object ID 指定，Gateway 透過 Microsoft Graph（client credentials，`src/identity/entra-directory.ts`）查到這個人，先建 User。之後登入時同一個 object ID 對到同一個 User
  - 需要 Graph 的 application permission `User.Read.All`，README 已補
  - Graph 連不上 → 502 `entra_unavailable`
- **Directory**（`src/directory/directory.ts`）：Workspace（名稱不分大小寫唯一）、membership（standing：`admin` / `member`）
  - **last-admin invariant**：降級或移除最後一位 Workspace Admin 會被拒（409 `last_workspace_admin`）。修改成員時先 `SELECT … FOR UPDATE` 鎖住 Workspace，一個 Workspace 的成員變更一次只做一個
- **REST**：
  - Platform Admin：`GET/POST /api/workspaces`、`PATCH/DELETE /api/workspaces/{id}`
  - 成員：`GET /api/workspaces/{id}`、`GET …/members`
  - Workspace Admin：`POST …/members`、`PATCH/DELETE …/members/{userId}`
  - 不屬於的 Workspace 一律 404（跟不存在一樣，不洩漏存在與否）；standing 不夠 → 403。Platform Admin 只管 Workspace 生命週期，不是成員就看不到成員
  - `/api/me` 的 `workspaces` 現在有資料，帶 `standing`
  - 錯誤統一由 `src/http/errors.ts` 轉成 `{error, message}`；request 驗證失敗 → 400 `invalid_request`
- **Migration** `0001_workspaces_and_memberships`：另外把 `users.last_signed_in_at` 改成可為 null（被加入但還沒登入的人）
- **Web UI**：首頁列出我的 Workspace 和身分；Platform Admin 區塊可以建立、改名、刪除；Workspace 頁面（`/workspaces/:id`）顯示成員，Workspace Admin 可以加人、升降級、移除
- fake Entra 加了 client credentials 和 Graph `GET /v1.0/users/{id|upn}`，可以用 `entra.graphDown = true` 模擬 Graph 掛掉
- 新增 26 個測試，共 68 個
