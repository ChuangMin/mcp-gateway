# #6 Tool Approval and re-discovery（2026-11-10）

分支 `6-tool-approval`，疊在 `5-upstream-servers`（PR #24）上。

## 完成了什麼

- **決策：approved tool 改變後一律暫停**，等 Workspace Admin 重新核准，不是只標記然後照樣能用。理由是描述改變跟 schema 改變一樣是擴權，因為 agent 是看描述決定要呼叫什麼。已寫進 ADR 0003 新增的一節，GLOSSARY 的 Tool Approval 也一併更新
- **Tool fingerprint**：對 `{description, inputSchema}` 取 canonical JSON 再算 SHA-256（`src/upstream/discovery.ts` 的 `toolFingerprint`），取代原本只看 schema 的指紋
  - 核准要帶上審查時看到的 fingerprint。檢查和寫入在同一條 UPDATE 裡完成，被核准的版本直接從該列複製，所以就算 discovery 同時改了 tool，也不會核准到沒看過的版本
- **狀態**：DB 只存決定（`pending` / `approved` / `rejected`）和被核准的版本（`approved_fingerprint`、`approved_description`、`approved_input_schema`）。API 顯示的 `changed` 是推導出來的：approved，但目前的 fingerprint 和核准時不同
  - 改回原本核准的版本就自動恢復 approved，不用額外處理
  - 撤銷（decision `pending`）會清掉被核准的版本
  - rejected 的 tool 改變後還是 rejected
- **消失的 tool**：設 `missing_since`，不刪資料列；API 不列出，也不能對它做決定。回來時清掉 `missing_since`，fingerprint 沒變就仍是 approved
- **Tool Discovery**（`src/upstream/discovery.ts`）：
  - 對每台 Upstream Server 保持一個 MCP session，收到 `notifications/tools/list_changed` 就重新偵測
  - 每 `TOOL_DISCOVERY_INTERVAL_SECONDS`（預設 300、最小 10）重新偵測一次。間隔照注入的 clock 算；檢查哪台到期的 tick 用真實時間（正式環境 5 秒，測試 20ms）
  - 同一台 server 的偵測一次只跑一個，執行中進來的要求合併成一次後續偵測
  - `reconnect` 用在換 credential 後；`forget` 用在取消註冊後。Workspace 被刪時 server 會被 cascade 刪除，下一個 tick 會發現並關掉 session
  - 失敗時標成 offline 並寫入 lastError，下次成功再恢復 online
- **Connector**：`probe` 改成 `connect` 並回傳 session（`listTools`、`open`、`close`）；close 時會送 DELETE 結束 session
- **Registry**：註冊和換 credential 都改走 discovery；新增 `decide()`，全有或全無：任何一個 tool 不存在回 404 `tool_not_found`，任何一個已改變回 409 `tool_changed`
- **REST**：`POST /api/workspaces/{id}/servers/{serverId}/tools/approval`，body 是 `{decision, tools: [{name, fingerprint?}]}`，回傳最新的 tool 列表
  - tool 新增 `fingerprint`、`previouslyApproved` 欄位；server 新增 `toolsAwaitingReview`（pending 加 changed 的數量）
- **Migration** `0003_tool_approval`：由兩次 drizzle-kit generate 手動合併而成，因為一次做 rename 會跳出互動式提示。舊資料先用舊指紋填入，下次 discovery 會重算
- **Web UI**：`ToolReview.tsx` 提供單個或批次的核准、拒絕、撤銷；changed 的 tool 會並排顯示核准版和目前版本；server 列表顯示待審數量
- **Fake upstream**：改成 stateful（每個 client 一個 session），新增 `notifyToolsChanged()` 和 `sessionCount`
- 新增 37 個測試，共 147 個
  - 反向驗證：分別拿掉 fingerprint 檢查、通知處理、changed 推導，以及把「標記消失」改成「刪除」，四種情況都會讓測試失敗

## 記得

- **暫存備份放 scratchpad，或用 git 還原**。上次誤寫到 `D:\` 根目錄，已經記進 memory
- 在 select 清單裡，Drizzle 的 `sql` 不會幫欄位名稱加上表名，相關子查詢必須手寫完整的欄位名稱
- **Discovery 的狀態都在記憶體裡**（session、最後嘗試時間）。如果之後要跑多個 Gateway instance，每台都會各自偵測：結果是對的，但會重複
- 不送 GET SSE 的 stateless upstream 收不到 list_changed 通知，只能靠定期偵測
