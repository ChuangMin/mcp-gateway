# One deployment serves one organization through one Entra Tenant

Each Gateway deployment trusts exactly one Microsoft Entra ID tenant for sign-in, and its multi-tenancy is internal: Workspaces are teams or departments of that one organization, not separate customer organizations. The project is self-hosted, so each organization runs its own deployment; serving several organizations from one deployment would add per-organization identity configuration and hard data isolation across organizations, which is hosted-SaaS work this project does not take on. Supporting several Entra tenants later would mean reworking sign-in and isolating data by organization above Workspaces. The Gateway's unit of isolation is called a Workspace rather than a "tenant", so that it is not confused with the Entra Tenant.
