# Newly discovered tools require Tool Approval, even under wildcards

When an Upstream Server starts offering a tool the Gateway has not seen before, that tool stays hidden from every User until a Workspace Admin approves it; a Role wildcard such as `github__*` covers only approved tools, never ones that appear later. Upstream Servers are run by third parties and can change without notice, and an upgrade that silently adds something like `github__delete_repo` to every Role holding `github__*` is exactly the unreviewed widening of access the Gateway exists to prevent. The cost is that admins must act before new tools are usable; we accept that. A future reader may take the wildcard's narrower meaning for a bug, but it is deliberate.

## Changes to an approved tool

An approval covers the version of the tool the Workspace Admin reviewed: its description and input schema, identified by a fingerprint over both. When re-discovery finds an approved tool with a different fingerprint, the tool is **suspended** (shown as `changed`) until a Workspace Admin approves the new version; it is not merely flagged while staying callable. A changed description is as much a widening as a changed schema, since agents decide what to call from the description, and "flag but keep serving" would let an upstream change take effect before anyone looked at it. If the tool changes back to the approved version it is approved again without action. Approving names the fingerprint the admin saw, so a tool that changed between review and click is refused rather than approved unseen. A tool the Upstream Server stops offering disappears from the Gateway but keeps its record, so it keeps its approval if it returns unchanged. A rejected tool stays rejected whatever changes.
